## 0. 一个意外的好消息：导出网关可以删掉

确认能装 APK 之后，采集端变成了**真正的 Android 应用**，于是多了一项能力——**它可以自己跑一个局域网 HTTP 服务**。

这意味着 v1.2 里那个"教室电脑上的单文件 exe"**完全不需要了**：

```
【旧】手表 → POST → 电脑上的网关 exe → 生成 xlsx → 微信发送
【新】手表 → 生成 xlsx 存本地 → 屏幕上显示二维码 → 老师扫码 → 浏览器直接下载
```

| 收益 | 说明 |
|---|---|
| 少一个组件 | 不用装 exe，不用配 IP，不用输配对码 |
| 少 3–4 天工期 | v1.2 的 S3 整个阶段被吸收进手表端 |
| 老师操作更简单 | **扫一个码，浏览器就下载了**，然后微信转发 |
| 不依赖 Windows | 手机、平板、Mac 都能收 |

**唯一的运行前提**：手表的这个页面要保持打开（服务只在页面存活期间运行），且与接收设备在同一 WiFi。

> 这也是为什么"能不能装 APK"这个问题值得花时间验证——它不只是换了个壳，而是把整条导出链路砍掉了一半。

```
│  │  · 存储：SQLite（/data/data/<pkg>/databases/lib.db） │  │
│  │  · 备份：每日快照 + 一键导出 .db                      │  │
│  │  · 导出：内置 HTTP 服务 + 自写 xlsx 生成器             │  │
│  └───────────────────────────────────────────────────┘  │
└───────────────────────────┬─────────────────────────────┘

              │ 老师手机 / 电脑浏览器          │
```

**三个"没有"**

| 没有 | 为什么能去掉 |
|---|---|
| 没有服务端 | 数据只在手表 SQLite 里，无同步、无账号、无并发 |
| 没有导出网关 | App 自己起 HTTP 服务，浏览器直连下载 |
| 没有云端 | 全程局域网，不出校园 |

## 2. 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 语言 | **Kotlin** | Android 事实标准 |
| UI | **XML View（不用 Compose）** | 1GB 内存下 Compose 的运行时开销不划算；这套界面只有 9 屏，XML 足够 |
| minSdk | **26（Android 8.0）** | 覆盖米兔 7（推测 8.1+），且避开 8.0 以下的存储坑 |
| targetSdk | **28** | 不追新，避免 scoped storage、前台服务类型等新限制 |
| 数据库 | **原生 SQLiteOpenHelper** | 不引 Room：省 1MB + 免 KAPT，表就 7 张，手写 DAO 更直接 |
| 扫码 | **CameraX + ZXing core**（`com.google.zxing:core`，约 500KB） | **不能用 ML Kit**——设备无 GMS |
| 拼音 | **TinyPinyin**（约 50KB） | 生成姓名全拼与首字母，语音匹配用 |
| 离线语音 | **Vosk-Android** + 中文小模型（约 40MB） | 无 GMS 就没有 Google 语音；Vosk 纯 Java API、可离线 |
| HTTP | **NanoHTTPD**（约 100KB）或自写 200 行 | 只服务一个下载接口，越轻越好 |
| xlsx | **自写极简 OOXML 生成器**（约 250 行） | 只需 3 个纯文本 sheet，引 POI 要 10MB+，不值得 |
| 打包 | Android Studio，`assembleDebug` 出 APK | 侧载不需要签名配置（debug 签名即可） |

**预计 APK 体积**：约 6MB（不含语音模型）；含 Vosk 模型约 46MB。8GB 存储无压力。

**明确不引入**：Retrofit、Glide、Hilt、Navigation、Compose、Room、Firebase、任何需要 GMS 的库。

## 3. 数据模型（完整 DDL）

### 3.1 设计约定

| 约定 | 说明 |
|---|---|
| 时间 | 一律 `INTEGER` 存 epoch millis（UTC），展示时转本地 |
| 布尔 | `INTEGER` 0/1 |
| 状态 | `TEXT` + `CHECK` 约束，让数据库自己挡住非法值 |
| 主键 | `INTEGER PRIMARY KEY AUTOINCREMENT`，但**业务上用条码做外部标识** |
| 版本 | `version` 字段用于状态变更的乐观校验 |

### 3.2 建表语句

```sql
PRAGMA foreign_keys = ON;

-- 名册
CREATE TABLE member (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    name        TEXT    NOT NULL,
    pinyin      TEXT    NOT NULL,
    initials    TEXT    NOT NULL,
    role        TEXT    NOT NULL DEFAULT 'student'
                        CHECK (role IN ('student','librarian','teacher')),
    status      TEXT    NOT NULL DEFAULT 'active'
                        CHECK (status IN ('active','left')),
    sort_no     INTEGER NOT NULL DEFAULT 0,
    created_at  INTEGER NOT NULL
);
CREATE INDEX idx_member_initials ON member(initials);
CREATE INDEX idx_member_pinyin   ON member(pinyin);

-- 书目
CREATE TABLE book (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    isbn        TEXT,
    title       TEXT    NOT NULL,
    author      TEXT,
    publisher   TEXT,
    category    TEXT    NOT NULL,
    source      TEXT    NOT NULL DEFAULT 'scan'
                        CHECK (source IN ('scan','voice','manual')),
    created_at  INTEGER NOT NULL
);
CREATE INDEX idx_book_title ON book(title);
CREATE INDEX idx_book_isbn  ON book(isbn);

-- 册（核心表）
CREATE TABLE copy (
    id             INTEGER PRIMARY KEY AUTOINCREMENT,
    book_id        INTEGER NOT NULL REFERENCES book(id),
    barcode        TEXT    NOT NULL UNIQUE,
    status         TEXT    NOT NULL DEFAULT 'in'
                           CHECK (status IN ('in','out','lost','removed')),
    owner_id       INTEGER REFERENCES member(id),
    shelf          TEXT,
    in_at          INTEGER NOT NULL,
    removed_reason TEXT,
    version        INTEGER NOT NULL DEFAULT 0
);
CREATE INDEX idx_copy_book    ON copy(book_id);
CREATE INDEX idx_copy_status  ON copy(status);
CREATE INDEX idx_copy_owner   ON copy(owner_id);

-- 借还记录
CREATE TABLE loan (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    copy_id       INTEGER NOT NULL REFERENCES copy(id),
    member_id     INTEGER NOT NULL REFERENCES member(id),
    borrowed_at   INTEGER NOT NULL,
    due_at        INTEGER NOT NULL,
    returned_at   INTEGER,
    status        TEXT    NOT NULL DEFAULT 'active'
                          CHECK (status IN ('active','returned','lost')),
    operator_id   INTEGER REFERENCES member(id)
);
CREATE INDEX idx_loan_copy   ON loan(copy_id, status);
CREATE INDEX idx_loan_member ON loan(member_id, status);
CREATE INDEX idx_loan_due    ON loan(due_at);

-- 【关键】一册书同时只能有一条 active 借阅，由数据库保证
CREATE UNIQUE INDEX ux_loan_one_active ON loan(copy_id) WHERE status = 'active';

-- 操作流水
CREATE TABLE op_log (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    action      TEXT    NOT NULL,
    target_type TEXT    NOT NULL,
    target_id   INTEGER NOT NULL,
    from_status TEXT,
    to_status   TEXT,
    operator_id INTEGER,
    note        TEXT,
    created_at  INTEGER NOT NULL
);
CREATE INDEX idx_op_target ON op_log(target_type, target_id);

-- 配置（借期天数、班级码等）
CREATE TABLE setting (
    key   TEXT PRIMARY KEY,
    value TEXT NOT NULL
);
```

### 3.3 两条值得说明的约束

**① 部分唯一索引 `ux_loan_one_active`**

```sql
CREATE UNIQUE INDEX ux_loan_one_active ON loan(copy_id) WHERE status = 'active';
```

这是整个 schema 里最有价值的一行。它把"一册书不能同时被两个人借着"这条业务规则**下沉到数据库层**——即使代码有 bug、即使并发写，数据库也会拒绝第二条 active 记录。比在应用层写 if 判断可靠得多。

**② `CHECK` 约束枚举状态**

`status` 只允许四个值。任何手误写进来的 `'borrowed'`、`'OUT'` 都会直接报错，避免"数据看起来对、实际查不到"的隐性 bug。

### 3.4 条码规则

```
barcode = 班级码(2) + 分类码(2) + 流水号(5)     共 9 位纯数字
例：030100123  = 三年级一班 / 01 童话 / 第 123 册
```

- 分类码取 `category` 的序号（1–99）
- 流水号取 `copy.id` 补零到 5 位
- `copy.id` 天然唯一 → 条码天然唯一，无需额外发号器
- 生成时机：**插入 copy 后再回填**（因为要用到自增 id），用同一事务完成

### 3.5 常用查询

```sql
-- 借出：校验 + 建单 + 改状态（必须在一个事务里）
BEGIN IMMEDIATE;
SELECT status, version FROM copy WHERE barcode = ?;
-- 校验 status='in'，否则回滚
INSERT INTO loan(copy_id, member_id, borrowed_at, due_at, status, operator_id)
     VALUES (?, ?, ?, ?, 'active', ?);
UPDATE copy SET status='out', version=version+1 WHERE id=? AND version=?;
COMMIT;
-- 若 UPDATE 影响行数 ≠ 1，说明有并发，整体回滚

-- 归还
BEGIN IMMEDIATE;
UPDATE loan SET status='returned', returned_at=? WHERE copy_id=? AND status='active';
UPDATE copy SET status='in', version=version+1 WHERE id=?;
COMMIT;

-- 在借清单
SELECT c.barcode, b.title, m.name, l.borrowed_at, l.due_at
  FROM loan l JOIN copy c ON c.id=l.copy_id
              JOIN book b ON b.id=c.book_id
              JOIN member m ON m.id=l.member_id
 WHERE l.status='active' ORDER BY l.due_at;

-- 超期
SELECT ... WHERE l.status='active' AND l.due_at < ?;
```

## 4. 关键实现要点

### 4.1 扫码：先枚举摄像头，再决定用哪个

米兔 7 有**前 500 万 + 侧 800 万**两个摄像头。Android 的 `CameraManager.getCameraIdList()` 会把它们都列出来，但**侧摄的 `LENS_FACING` 标注不一定可靠**（可能被标成 BACK，也可能标成 EXTERNAL）。

**不要硬编码"用后置"**，做法是：

| 步 | 做法 |
|---|---|
| 1 | 启动时枚举所有 cameraId，读取各自的 `LENS_FACING`、支持分辨率、`LENS_INFO_MINIMUM_FOCUS_DISTANCE` |
| 2 | 设置页提供「扫码摄像头」选项，列出全部摄像头让用户选 |
| 3 | 默认选**最近对焦距离最小**的那个（扫书要近距离） |
| 4 | 记住选择，下次直接用 |

> **这是个必须做的小功能**：如果默认选错摄像头（比如选了前置自拍镜头），扫码会一直对不上焦，而用户不知道能改。

**解码**：ZXing 直接用 `MultiFormatReader`，同时支持 QR 与 Code128（标签上两种码都有）。取景框只解码中央区域，可以显著提速并减少误识别。

### 4.2 语音：三级降级，任何一级能用就不往下走

| 级 | 方案 | 前提 | 体验 |
|---|---|---|---|
| **L1** | `RecognizerIntent.ACTION_RECOGNIZE_SPEECH` 调系统识别器 | 米兔系统注册了识别器（小爱同学可能注册） | 点一下说名字，2 秒返回 |
| **L2** | **Vosk 离线识别**（中文小模型 ~40MB） | 无 | 首次加载模型 2–3 秒，之后离线可用 |
| **L3** | 快选：最近 8 人 + 首字母筛选 | 无 | 5 秒 |

**先测 L1，测不到直接上 L2**，L3 永远保留作为兜底（不因语音失败而阻断流程）。

> **L1 的检测方法**：用 `PackageManager.queryIntentActivities()` 查有没有 Activity 响应 `ACTION_RECOGNIZE_SPEECH`。这一步 5 分钟就能测出来，建议列进 S1 的第一件事。

### 4.3 语音匹配算法（与平台无关，是纯文本处理）

拿到文本后不直接当名字，而是走四级匹配：

| 级 | 规则 | 例 |
|---|---|---|
| 1 | 完全相等 | `王小明` |
| 2 | 无声调全拼相等 | `wangxiaoming` |
| 3 | 首字母相等 | `wxm` |
| 4 | 拼音编辑距离 ≤ 2 | 误识为 `王晓明` 仍命中 |

**结果处理**：唯一命中 → 自动填入；多候选 → 列 2–3 个让人点；零命中 → 提示重说，同时给快选入口。

> 这套算法让 ASR 只需要"大致对"。Vosk 小模型在这种短词识别上可能只有 70–80% 字准确率，但候选空间只有 45 个，经过拼音归一后命中率能到 90%+。**这是整个语音方案成立的关键，也是为什么必须先建好名册再谈语音。**

### 4.4 状态变更必须走事务

四个状态之间的 8 条转移（T1–T8），**每一条都要保证"改 copy 状态"与"写 loan / 写 op_log"在同一个事务内完成**。

否则会出现最糟糕的数据形态：**借阅单建了，但书的状态没改**。这种不一致在本地库里没有"事后对账"的机会，只能靠事务防住。

实现上用 `beginTransaction()` / `setTransactionSuccessful()` / `endTransaction()`，配合 3.3 的部分唯一索引兜底。

## 5. 界面规格（360×390）

> 米兔 7 是 1.68 英寸 360×390 方形屏，比 6C 的 240×240 宽裕不少。按**一屏一件事**设计，不做滚动页。

## 6. 导出：App 内起 HTTP 服务

### 6.1 流程

```
用户点「生成报表」
  ↓
App 生成 xlsx 到私有目录，同时在内存里备一份
  ↓
启动 NanoHTTPD（绑定 0.0.0.0:8080，随机端口更佳）
  ↓
屏幕显示：二维码（含 http://192.168.x.x:8080/r?t=abc123）+ 地址大字
  ↓
老师手机/电脑扫码 → 浏览器打开 → 直接下载 班级图书角_20261020.xlsx
  ↓
老师微信转发
```

### 6.2 四条实现要求

| 要求 | 说明 |
|---|---|
| **一次性 token** | URL 带随机 token，10 分钟失效，防止同网段其他人乱下 |
| **只暴露一个路径** | 其余路径一律 404。这个服务是临时开的，必须最小化 |
| **页面退出即停服务** | 不做前台服务，避免常驻耗电与通知栏打扰 |
| **显示 IP** | 二维码旁边用大字印出 `192.168.x.x:8080`，扫不出来时可以手输 |

### 6.3 xlsx 生成

**自写极简 OOXML**，不引 POI。xlsx 本质是一个 zip，里面几个 XML：

```
[Content_Types].xml
_rels/.rels
xl/workbook.xml
xl/_rels/workbook.xml.rels
xl/worksheets/sheet1.xml   ← 书籍清单
xl/worksheets/sheet2.xml   ← 借还记录
xl/worksheets/sheet3.xml   ← 概览
```

只写纯文本单元格（`<c t="inlineStr"><is><t>…</t></is></c>`），不做样式、不做公式、不做合并。**800 行数据生成耗时 < 200ms**。

> 这样做的好处：零依赖、APK 不增加体积、完全可控。代价是要自己处理 XML 转义（`&<>` 三个字符），这是唯一的坑。

三个 sheet 的列见 §7。

## 7. 导出内容（三个 sheet）

### Sheet 1 · 书籍清单

| 列 | 来源 |
|---|---|
| 序号 / 书名 / 作者 / ISBN / 分类 | book |
| 条码 | copy.barcode |
| **所有者** | member.name（copy.owner_id） |
| **状态** | copy.status 转中文（入库/借出/遗失/出库） |
| 书架位 / 入库日期 / 出库原因 | copy |

### Sheet 2 · 借还记录

| 列 | 来源 |
|---|---|
| 序号 / 书名 / 条码 | join |
| **借出人** | member.name |
| 借出日期 / 应还日期 / 归还日期 | loan |
| 状态 | active→未还，且 due_at < now→超期未还；returned→已还；lost→遗失 |
| 操作人 | operator_id |

### Sheet 3 · 概览

| 区块 | 内容 |
|---|---|
| 总量 | 总册数 / 在库 / 借出 / 遗失 / 出库 |
| **超期未还** | 姓名 + 书名 + 超期天数（按天数倒序） |
| **所有者分布** | 每位同学名下几本书（老师做动员用） |
| 零借阅 | 从未被借出的书 |

## 8. 构建、安装、入口

### 8.1 构建

```
Android Studio → Open 项目 → Build → Build APK(s)
产物：app/build/outputs/apk/debug/app-debug.apk
```

debug 签名即可侧载，不需要配置 release keystore（如果将来要分享给别的班，再考虑正式签名）。

### 8.2 安装

| 方式 | 步骤 |
|---|---|
| **推荐** | `adb install -r app-debug.apk`（手表已开 ADB） |
| 备选 | 把 APK 传到手表存储，用文件管理器点击安装 |

装完**不会自动出现在桌面**——米兔原厂桌面只显示白名单应用。启动入口优先级：

1. 售后测试页里的「三方应用」列表（最稳）
2. 装一个轻量 launcher，从 launcher 里启动
3. 若支持快捷方式，加桌面图标

> 这一步需要在 S1 第一周就确定下来，因为它影响"孩子每天怎么打开这个 App"。**建议做一个最省事的方案：手表上把它设成某个可长按/快捷唤起的方式**，否则 10 岁孩子每次都要绕到售后页，用不了三天就放弃。

### 8.3 首次使用

```
① 导入名册（粘贴 45 个名字 → 自动生成拼音）
② 设置借期（默认 14 天）、班级码、分类
③ 选扫码摄像头（枚举后逐个试，选对焦最好的）
④ 测语音（L1 系统识别器 / L2 Vosk）
⑤ 录入第一本书 → 打印标签 → 试一次借还
```

## 9. 数据安全（本地单设备的必答题）

| 措施 | 做法 | 优先级 |
|---|---|---|
| **每日快照** | 每次启动时把 `lib.db` 复制到 `files/backup/lib_yyyyMMdd.db`，保留 7 份 | P0 |
| **导出即备份** | 每次导出报表，同时把 `.db` 也放进下载列表（老师可一并保存） | P0 |
| **一键恢复** | 设置页可从任一快照恢复，恢复前先备份当前库 | P1 |
| **升级不丢数据** | `onUpgrade` 里只做 `ALTER TABLE ADD COLUMN`，绝不 `DROP` | P0 |
| **明确告知** | 首次启动弹一句：「数据只存在这台手表里，请定期导出备份」 | P0 |

> 单设备本地的最大风险不是"被黑"，是**丢失**。手表摔了、丢了、恢复出厂，数据就没了。所以备份不是可选项。

## 11. 风险
