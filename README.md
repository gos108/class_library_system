# 班级图书角系统

给小学班级图书角做的一套轻量工具。**采集端是一个装在米兔儿童手表上的 Android App**，数据全部存在手表本地 SQLite，不依赖服务器、不依赖云。

> 当前状态：**v0.4.0**。入库、借出、归还、查书、遗失/出库、报表导出全部可用，已在无头模拟器上真实点击走通。**尚未在米兔手表真机上运行过**——扫码解码与 Vosk 中文识别是两项未验证的能力。

---

## 这解决什么问题

班级图书角通常只有一本纸质登记本，结果是：

- 谁借了什么、还没还，全靠翻本子
- 同学带来共享的书，期末要还回去，但说不清哪本是谁的
- 书丢了没人知道是什么时候丢的

系统只做四件事：记录**书籍**、**所有者**、**借还状态**、**借还人**；老师要报表时导出 Excel。

## 关键设计

| 决策 | 说明 |
|---|---|
| **数据在手表本地** | 无服务端、无账号、无同步，也就没有并发与冲突问题 |
| **书籍状态只有 4 种** | 入库 / 借出 / 遗失 / 出库。不做磨损等级——判的人是 10 岁孩子，级数越多越判不准 |
| **书目与副本分离** | 一种书多册，各自独立条码。否则"还剩几本在架"无法回答 |
| **扫码 + 语音两条输入** | 手表屏幕 1.68 英寸，几乎无法打字。刷 ISBN 带出书名，说一句话选人 |
| **不做归还提醒** | 提醒需要触达家庭，而系统刻意不采集家长信息 |
| **导出走局域网 HTTP** | App 自己起一个临时服务，屏幕上显示二维码，老师扫码直接下载 xlsx（S3 实现） |

## 快速开始

### 1. 环境

Android Studio Hedgehog 2023.1.1+（JDK 17），Gradle 8.0，AGP 8.1.4，Kotlin 1.9.10。
`compileSdk 34 / minSdk 26 / targetSdk 28`（压到 28 是为了避开分区存储与后台限制）。

### 2. 构建

```bash
./gradlew assembleDebug
# 产物 app/build/outputs/apk/debug/app-debug.apk
```

### 3. 装到手表

手表需先在售后测试页开启 USB 调试：

```bash
adb devices
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

装完不会出现在原厂桌面（白名单限制），启动入口按优先级尝试：售后测试页的「三方应用」→ 轻量 launcher → 快捷方式。

### 4. 语音模型

APK 不含模型，需手动放：

1. 下载 <https://alphacephei.com/vosk/models/vosk-model-small-cn-0.22.zip>
2. 解压，把目录内**全部内容**放进 `app/src/main/assets/model-cn/`
3. 重新构建

没有模型也能跑，语音自动降级为「点选名单」。

## 已实现 / 未实现

**已实现**
- 7 张表的完整 DDL，含 `ux_loan_one_active` 部分唯一索引（一册书同时只能有一条 active 借阅，由数据库保证）
- DAO：Member / Book / Copy / Loan / CopyStatus / Report
- 名册：粘贴导入、拼音与首字母自动生成、去重
- 扫码：CameraX + ZXing，支持 QR / Code128 / EAN-13，可切换前摄与侧摄
- 入库：扫 ISBN → 在线带出书名 → 选分类 / 所有者 / 册数 → 生成 9 位短码
- 借出 / 归还 / 查书：**认出版商 ISBN**，也认系统内 9 位码和书名关键词
- 遗失 / 出库 / 撤销：必选原因 + 二次确认，借出中改遗失会一并关闭借阅单
- 语音：系统识别器 → Vosk 离线 → 名单点选，三级降级
- 报表导出：手表热点 + 索引页扫码下载，xlsx（4 sheet）+ backup.json（可重建全库）

**未实现**
- 标签打印 —— 已决定不做，理由见下
- 每日自动备份 —— 已决定不做，理由见下
- 备份 json 的一键恢复（文件已可重建，缺导入入口）

## 两处刻意的「不做」

**不印标签、不贴标签。** 内码只存在于数据库里，书上没有，所以贴标签的唯一作用是让借还能被扫到。但这件事本该由查询解决：直接认封底的出版商 ISBN，多册同书时取一册在库的即可（物理上可互换）。800 册贴一遍约 4 小时人工，且会磨花、翘边、换班重来——为一个能用一次代码修掉的问题付出这个代价不划算。

代价是：多册同 ISBN 且所有者不同、又恰好那册遗失时，归属只能精确到「这几本之一」。实际退书时人一眼能分。

**不做每日自动备份。** 同一台设备上的快照防不住它想防的事：手表丢了 / 摔了 / 恢复出厂，快照一起没；系统清应用数据，快照在 `/data/data/` 里也一起被清。它唯一能防的是「数据库文件被写坏」，而 SQLite 单写者 + 事务 + journal 已经堵得很死。

真正的备份必须离开设备，所以导出时同时给一份 `backup.json`（全库转储 + 配置），并用首页「上次导出 N 天前」提醒人定期做——**一行提示比一个沉默的定时任务有用**。

## 已知限制

- **未在真机运行过**：编译与运行验证都在 x86_64 模拟器上完成。真实扫码解码（模拟器相机无画面）和 Vosk 中文识别（模型未随包分发）两项能力尚未验证。
- 手表是儿童安全设备，侧载属于非官方手段。**不要在家用唯一通讯/定位设备上做**。
- 单设备本地存储意味着**手表丢失 = 数据丢失**，必须定期导出。首页会提示「上次导出 N 天前」。
- 没有登录体系，`op_log.operator_id` 目前为 NULL；班级里多人共用一台设备时无法区分操作人。
